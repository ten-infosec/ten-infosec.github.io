흉부 X-ray 폐렴 분류

2026.09.22 – 2026.10.18 · 개인

GitHub 저장소

소아 흉부 X-ray 5,216장으로 정상과 폐렴을 분류했습니다. 점수를 올리기보다 검증 점수와 실제 점수가 왜 다른지를 먼저 찾고, Grad-CAM으로 모델의 판단 근거까지 검증했습니다. 모든 실험은 한 번에 하나씩만 바꿔 효과를 분리하고 매일 데일리 로그로 기록했습니다.

문제 해결 과정

검증 0.95, 리더보드 0.75 — 20%p 격차의 원인 찾기

AS-IS

공식 Baseline은 검증 Accuracy 0.9454인데 리더보드는 0.7468이었습니다. 테스트에서 폐렴 확률 중앙값이 0.98에서 0.50으로 떨어져, 모델이 확신 없이 헷갈리고 있었습니다.

TO-BE

학습 이미지는 224×224로 가공되어 검은 여백이 있고, 테스트는 원본 크기라 여백이 없다는 것을 확인했습니다. 폐렴 이미지일수록 여백이 많아(31.5% vs 17.6%) 지름길 단서가 될 수 있었습니다. 사전학습 ResNet18을 전체 미세조정해 격차를 19.9%p → 3.9%p로 줄였습니다.

검증은 최고, 리더보드는 하락 — Crop 가설 기각

AS-IS

여백을 잘라내면 지름길이 사라질 거라 예상했지만, 검증 AUC는 0.9988로 최고였는데 리더보드는 0.9407 → 0.9022로 떨어졌습니다.

TO-BE

잘라낸 뒤 가로세로 비율이 정상 1.19 / 폐렴 1.47 / 테스트 1.46으로 달라 "넓적한 이미지 = 폐렴"이라는 새 지름길이 생긴 것을 확인했습니다. 이후 테스트 정상 예측 비율을 제출 전 간접 지표로 쓰고, 최종 모델은 E1b로 유지했습니다.

Grad-CAM으로 높은 점수 뒤의 근거 확인

AS-IS

리더보드 0.94라는 숫자만으로는 모델이 폐를 보고 판단하는지 알 수 없었습니다.

TO-BE

Grad-CAM을 직접 구현하고 열지도가 테두리 15%에 몰린 비율을 지표로 만들었습니다. 정상 판정은 0.21로 폐 중앙을 봤지만 오진한 3장은 0.68로 검은 모서리를 봤습니다. 이를 한계로 명시하고 확률 기반 Risk Level을 설계해 의료진 확인 단계를 두었습니다.

학습 안 된 모델이 제출된 실수를 스스로 발견

AS-IS

첫 제출 점수가 0.625로 "전부 폐렴"과 같았고, 테스트 예측이 모두 0.51~0.54에 몰려 있었습니다.

TO-BE

미리 넣어둔 재로드 검증 코드에서 AUC 0.38이 나와, 빈 모델이 저장된 실행 순서 문제를 찾았습니다. 이후 처음부터 다시 실행해 테스트 예측 차이 0 / 624로 재현성을 확인했습니다.

STACKPython, PyTorch, torchvision(ResNet18), Grad-CAM(직접 구현), scikit-learn, Google Colab

문제 해결 과정

20개 넘는 컬럼에 몰린 결측치 — 빈칸의 이유 찾기

AS-IS

배아 생성 수, 이식 경과일 등 20개 넘는 컬럼에 결측치가 몰려 있었습니다. 평균으로 채우면 간단하지만 의미 있는 패턴일 수 있었습니다.

TO-BE

비어 있는 행은 정확히 DI(인공수정) 시술 환자 6,291명이었습니다. DI는 체외에서 배아를 만들지 않아 배아 관련 값이 원래 없는 것이었고, 평균 대체 대신 결측 자체를 정보로 유지했습니다.

제공 베이스라인을 그대로 믿지 않기

AS-IS

부트캠프에서 제공한 베이스라인 노트북이 실행되지 않았고, 결과도 신뢰하기 어려운 상태였습니다.

TO-BE

컬럼명이 실제 데이터와 다르고, 분류 문제를 회귀로 가정하고 있던 것을 찾아 팀에 공유하고, EDA부터 베이스라인까지 파이프라인을 다시 구축했습니다.

불균형 보정이 AUC를 바꾸지 않은 이유

AS-IS

성공이 25.8%뿐이라 클래스 가중치(scale_pos_weight)를 주면 성능이 오를 거라 예상했습니다.

TO-BE

재현율은 21% → 76%로 올랐지만 AUC는 그대로였습니다. AUC는 기준값과 무관하게 순위로 구분력을 보는 지표라, 가중치는 기준선만 옮길 뿐임을 확인했습니다.

제출 직전에 발견한 두 가지 버그

AS-IS

XGBoost가 테스트에만 있는 범주 값에서 에러를 냈고, 제출 파일의 확률 컬럼이 전부 0으로 저장되고 있었습니다.

TO-BE

학습·테스트를 합쳐 같은 기준으로 범주를 변환하고, 예측값이 엉뚱한 컬럼에 들어가던 문제를 고쳤습니다. 제출 전 예측값 통계를 출력하는 검증 단계를 추가해 9만 건 정상 제출을 확인했습니다.

STACKPython, Pandas, scikit-learn, XGBoost, LightGBM, CatBoost, Optuna, SHAP
